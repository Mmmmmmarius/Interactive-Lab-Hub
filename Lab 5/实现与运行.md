# Touch grass score：实现与运行

此页记录本作品的实现和运行方式，不替代 Part F 的个人分镜和真实反馈。当前执行结果见本文末尾，设计说明不代表实测完成。

## 已确定的日常流程

每天纽约时间 8 点开始，摄像头每五分钟保存一张照片。睡前按 Mini PiTFT 的任意一个按钮，停止当天采集并启动处理。长按算一次，处理中重复按不会创建另一任务。下一个早上 8 点开始新一批。

午夜之后、早上 8 点之前按按钮，仍处理前一天 8 点开始的批次。如果漏按一天，旧数据保留，下一天单独建批次，不伪造缺失照片。初次部署后的正式采集从下一个早上 8 点开始。

YOLO 把每个采样转成是否检测到人的记录。Python 汇总有人、无人和未知的样本数量，并把数量与采样间隔交给 Qwen。Qwen 计算桌前分钟数和 0–100 分，并生成说明。

Python 校验字段、数量、运算关系、分数上下限和模拟标签。校验只接受或拒绝，不替换、修正或生成模型的时长及分数。失败时最多请求三次，每次提示、模型原答和失败原因单独保存。三次都失败则显示需要检查，不填入程序算出的结果。

为使每天的分数有同一尺度，当前提示词使用 Codex 提出的实现刻度：0 小时为 0 分、2 小时为 25 分、4 小时为 50 分、6 小时为 75 分、8 小时及以上为 100 分。换算由 Qwen 完成。这是可调整的实现参数，不是课程规则或用户此前指定的八小时目标。

固定摄像头朝向书桌。当前版本检测整幅桌面视野中的人物，没有身份识别，也不能证明被检测的人在操作电脑。采样、遮挡和模型计算都可能带来误差。短时检查标注为 Setup test，不作为全天记录。

当前使用已安装的 `qwen3:0.6b`，开启推理。评分表达式在提示词中写为桌前分钟数除以 4.8，再取整并限制在一百分以内。这与八小时对应一百分的刻度相同，运算仍由 Qwen 完成。`qwen3.5:0.8b` 的关闭推理版本有计算错误，开启推理时未能在本轮预算内返回最终答案，比较结果均保留。

## 部署步骤

本机未找到适用于这个 Pi 项目的部署指南，因此先写此流程，再按步骤执行。复用现有 Python 环境，不安装新 Python 包。

1. 将上述源码复制到 Pi 的独立程序目录。主程序使用 Lab 5 的虚拟环境，屏幕程序使用现有 `/home/pi/venv`。
2. 在 `config.json` 写入纽约时区的首次采集日期、模型目录、数据目录和网页端口。默认端口为 8080。
3. 用 `app.py --prepare-test` 拍三张短时检查照片，保存为独立标注的当天测试批次。常规定时拍摄仍等待首次采集日期。
4. 建立 `touch-grass.service` 和 `touch-grass-screen.service`。新屏幕服务与旧 `piscreen.service` 冲突，停止旧服务并保留其配置，再启动新服务。失败时恢复旧服务。
5. 核对内网页面、原始数据和屏幕程序状态。服务启动检查通过后启用开机启动，旧屏幕服务保持停用以避免同时抢占 GPIO。实体按键由 Marius 另行验证，不将服务心跳当作按键验收。

## 操作与恢复

另有独立的 [15 分钟快速演示](%E5%BF%AB%E9%80%9F%E6%BC%94%E7%A4%BA.md)。第一次按钮开始真实采集，每 30 秒一张，到点停止，第二次按钮启动分析。分析将每格解释为模拟的 24 分钟，组成 08:00–20:00 的模拟白天。真实采样和模拟标签分别保存。演示使用独立的 `store/demos/`，不覆盖 `store/days/` 的日常记录。

打开 [Touch grass 内网页面](http://192.168.1.39:8080)。网页供查看日期、状态、估算时长、分数和原始记录，开始处理使用实体按钮。当前地址由路由器分配，如果 Pi 的地址改变，需要使用新地址访问。

```bash
sudo systemctl status touch-grass.service touch-grass-screen.service
sudo journalctl -u touch-grass.service -u touch-grass-screen.service -n 40 --no-pager
```

若要停止本项目并恢复原来的网络信息屏幕：

```bash
sudo systemctl disable --now touch-grass-screen.service touch-grass.service
sudo systemctl enable --now piscreen.service
```

上述停止方式保留照片和原始报告。原始照片保留在 Pi 上，演示后的清理由 Marius 确定。Web 控制入口不提供删除文件的功能。

## 草宠物网页的构建与部署

Grass bro 已部署到 [Pi 内网页面](http://192.168.1.39:8080/)。时长与分数来自原有 Qwen 报告，点击宠物只切换前端台词。当前演示仍是 552 模拟分钟、100 分。新截图与部署记录见 [界面检查](_%E8%AF%81%E6%8D%AE/grass-ui/README.md)。

源代码位于 `Study HQ/Projects/INFO5345/Lab5/touch_grass/ui/`。角色和文案在 `grass-bro.js`，报告与状态选择在 `view-state.js`，页面行为在 `page.js`。HTML 和 CSS 也在这个目录。修改源文件后，在工作区根目录运行：

```powershell
node 'Study HQ/Projects/INFO5345/Lab5/touch_grass/build-ui.cjs'
node 'Study HQ/Projects/INFO5345/Lab5/touch_grass/test-ui.cjs'
```

构建生成 `web/index.html`、`web/style.css` 和 `web/app.js`。Pi 原有服务只公开这三个文件，因此将角色合并进脚本，不增加路由、安装包或外部资源请求。

部署前先备份 Pi 的 `web/`。本轮旧页面保存在 `/home/pi/touch-grass/backups/grass-ui-20261102-012015/web/`。将新文件以 `.incoming` 后缀上传，逐个原子替换，最后替换 HTML。服务会读取新文件，浏览器刷新即可，不需要重启采集或 TFT 服务。恢复时从该备份取回这三个静态文件，采用同样的临时文件替换方式，然后刷新浏览器。

本轮核对了部署文件与 HTTP 返回的一致性、后端与演示数据不变、两个服务保持原进程、实时 YOLO 保持运行。下一次需要摄像头采集前，仍应在 YOLO 窗口按 `q` 退出以释放摄像头。
